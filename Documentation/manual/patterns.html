Chat Patterns

MQMyDPS recognizes damage, healing, and miss messages by matching them against a set of chat patterns. These patterns are fully customizable, letting you adapt the plugin to different server types (live, emulated, custom) where combat messages may differ.

How It Works

When EverQuest prints a combat message in your chat window, MQMyDPS compares it against every enabled pattern. If a pattern matches, the plugin extracts the relevant values (target name, damage amount, spell name, etc.) and records the event. Each pattern is tied to a specific damage type (melee, DoT, heal, etc.) that determines how the event is categorized.

The default patterns work out of the box for standard EverQuest servers. You only need to edit them if your server uses non-standard combat message formats.

Where Patterns Are Stored

Patterns are saved in a JSON file specific to each server:

[MQ Config Directory]\MQMyDPS\[ServerName]\Patterns.json

The first time you load MQMyDPS on a server, this file is created automatically with all default patterns. The file is shared across all characters on that server.

The Patterns Tab

You can view and edit patterns in-game through the Patterns tab in the settings window (/mydps config). The tab shows two tables:

Chat Patterns

These match your own damage, healing, and miss messages. Each row has:

  • Enable checkbox — Toggle the pattern on or off without deleting it
  • Key — The internal name that identifies the pattern type (e.g., "melee", "dot", "crit_heal"). The Key is read-only in the tab; new pattern keys can only be added by editing the JSON file directly.
  • Pattern — The text pattern to match, with named captures and tokens. The current pattern is shown as read-only text; click it to open a small editor at your cursor. Make your change there and press Accept (or Enter) to apply it, or Cancel (or Esc) to discard it — the pattern only changes when you accept.

Pet Patterns

These match damage dealt by your pet. They work the same as chat patterns but use the {PetName} token to match your pet's current name.

Applying Changes

After editing patterns in the tab:

  1. Click Save to write changes to the JSON file
  2. Click Reload to re-register all patterns with the matching engine

You can also reload from chat with:

/mydps patterns reload
Changes to patterns only take effect after a reload. Simply editing the text in the tab does not immediately change how messages are matched.

Pattern Syntax

Patterns use a straightforward syntax to match EverQuest chat messages.

Named Captures

Named captures extract specific values from a message. They are written with # delimiters:

CaptureWhat It Extracts
#target#The name of the target being hit or healed
#damage#The numeric damage or healing amount
#verb#The attack verb (slash, crush, pierce, kick, etc.)
#spell#The name of the spell or ability
#attacker#The name of whoever is attacking you
#healer#The name of whoever healed you

Wildcards

Use #*# to match any text you do not need to capture. This is useful for matching messages where some parts vary but you only care about specific values.

Tokens

Tokens are placeholders that are replaced with actual values when the pattern is registered:

TokenReplaced With
{CharName}Your character's name
{PetName}Your pet's current name (pet patterns only)

Default Patterns

These are the patterns included by default. They match standard EverQuest combat messages.

Damage Patterns

KeyPatternExample Match
melee You #verb# #target# for #damage# points of damage. You slash a gnoll for 150 points of damage.
miss You try to #verb# #target#, but miss! You try to slash a gnoll, but miss!
non_melee {CharName} hit #target# for #damage# points of non-melee damage. Soandso hit a gnoll for 500 points of non-melee damage.
crit #*#You score a critical hit!#*#(#damage#) You score a critical hit!(300)
crit_blast #*#You deliver a critical blast!#*#(#damage#) You deliver a critical blast!(800)
deadly_strike #*#{CharName} scores a Deadly Strike!#*#(#damage#) Soandso scores a Deadly Strike!(1200)
dot #target# has taken #damage# damage from your #spell#. A gnoll has taken 200 damage from your Flame Lick.
damage_shield #target# was hit by non-melee for #damage# points of damage. A gnoll was hit by non-melee for 50 points of damage.

Incoming Damage Patterns

KeyPatternExample Match
hit_by #attacker# #verb# YOU for #damage# points of damage. A gnoll slashes YOU for 100 points of damage.
missed_me #attacker# tries to #verb# YOU, but misses! A gnoll tries to slash YOU, but misses!
hit_by_non_melee #attacker# hit YOU for #damage# points of non-melee damage. A gnoll hit YOU for 300 points of non-melee damage.

Healing Patterns

KeyPatternExample Match
crit_heal #*#You perform an exceptional heal!#*#(#damage#) You perform an exceptional heal!(450)
direct_heal You have healed #target# for #damage# hit points with your #spell#. You have healed Soandso for 400 hit points with your Light Healing.
direct_heal_simple You have healed #target# for #damage# points. You have healed Soandso for 400 points.
healed_by #healer# healed you for #damage# hit points by #spell#. Clericname healed you for 500 hit points by Complete Heal.

Pet Patterns

KeyPatternExample Match
pet_melee {PetName} #verb# #target# for #damage# points of damage. Xabtik hits a gnoll for 75 points of damage.
pet_non_melee {PetName} hit #target# for #damage# points of non-melee damage. Xabtik hit a gnoll for 200 points of non-melee damage.

Editing the JSON File Directly

You can also edit the Patterns.json file with any text editor. The file structure looks like this:

{
    "version": 2,
    "patterns": {
        "melee": {
            "type": "Melee",
            "pattern": "You #verb# #target# for #damage# points of damage.",
            "enabled": true
        },
        "dot": {
            "type": "DoT",
            "pattern": "#target# has taken #damage# damage from your #spell#.",
            "enabled": true
        }
    },
    "pet_patterns": {
        "pet_melee": {
            "type": "PetMelee",
            "pattern": "{PetName} #verb# #target# for #damage# points of damage.",
            "enabled": true
        }
    }
}

After saving your edits, run /mydps patterns reload in-game to apply the changes.

Be careful with the pattern text. The trailing punctuation (periods, exclamation marks) must match exactly what EverQuest prints. A missing period at the end of a pattern will prevent it from matching.

Writing Custom Patterns

If your server uses non-standard combat messages, you can modify the existing patterns or add new ones to match. Here are some guidelines:

  • The literal text in your pattern must match the chat message exactly, including punctuation and capitalization
  • Use named captures (#name#) for the parts that change between messages
  • Use wildcards (#*#) to skip over variable-length text you do not need
  • Use {CharName} wherever your character name appears in the message
  • The key name must match one of the recognized types (melee, miss, non_melee, crit, crit_blast, deadly_strike, dot, damage_shield, hit_by, missed_me, crit_heal, direct_heal, direct_heal_simple, healed_by, hit_by_non_melee, pet_melee, pet_non_melee)
  • Each key can only appear once in the pattern list

Version Upgrades

When MQMyDPS updates its default patterns (for example, to fix a pattern that was not matching correctly), it may need to upgrade your Patterns.json file. If your file has an older version number, the plugin will automatically regenerate default patterns and save a new file. A message in chat will tell you when this happens.

If you have customized your patterns and an upgrade resets them, you can restore your changes by editing the new JSON file. Version upgrades only happen when a pattern fix is important enough to require it.

Troubleshooting

A pattern is not matching

  • Make sure the pattern is enabled (checkbox is checked in the Patterns tab)
  • Verify that the literal text matches exactly what appears in your EQ chat window, including punctuation at the end
  • Make sure you clicked Save and then Reload after making changes
  • Check that {CharName} is being used where your character name appears (not your actual name typed literally)

Pet damage is not being tracked

  • Make sure Track Pet is enabled in the Display settings tab
  • Pet patterns are registered dynamically when your pet is detected. If you just summoned a pet, give it a moment to be recognized
  • Check that the pet patterns use {PetName} and not a hardcoded pet name
