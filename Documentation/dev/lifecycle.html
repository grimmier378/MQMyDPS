Plugin Lifecycle

Plugin Callbacks

MacroQuest calls these entry points at specific moments in the plugin and game lifecycle. All are defined in MQMyDPS.cpp.

250ms throttle: The OnPulse throttle prevents expensive operations like GetCombatState() and XTarget list scans from running hundreds of times per second. EQ ticks at roughly 60 FPS, so without the throttle these would run ~60 times/sec. The 250ms interval (4 times/sec) is sufficient for combat state tracking and DoT monitoring while keeping CPU usage negligible.

Combat State Machine

Combat tracking uses a three-state machine with a configurable delay before finalizing a battle. This prevents brief non-combat windows (mob running, fear, root breaks) from splitting a single fight into multiple battles.

IDLE (inCombat=false) | | RecordDamage: outgoing damage detected | (isDamageOut && !isMiss && damage > 0) v ACTIVE (inCombat=true, m_combatEndPending=false) | | UpdateCombatState: GetCombatState() != eCombatState_Combat | Sets m_combatEndPending=true, records m_leftCombatTime v PENDING_END (inCombat=true, m_combatEndPending=true) | +-- GetCombatState() == Combat --> back to ACTIVE (pending cleared) | +-- elapsed >= battleEndDelay --> FinalizeBattle() | v IDLE

IDLE to ACTIVE

RecordDamage (MQMyDPS.cpp:661) detects outgoing damage and transitions to ACTIVE. The isDamageOut flag excludes incoming damage types: HitBy, HitByNonMelee, MissedMe, CritHeal, and DirectHeal. Additionally, misses (isMiss) and zero-damage records do not trigger combat start.

On transition, the engine resets all per-battle accumulators (battleDamage, battleCritDamage, battleDotDamage, battlePetDamage, battleNonMeleeDmg, battleDsDamage, battleDirectHeals, battleCritHeals, battleHitCount), clears currentTargets and currentHealTargets, and records battleStartTime.

ACTIVE to PENDING_END

UpdateCombatState (MQMyDPS.cpp:894) runs every 250ms and checks GetCombatState(). When the game reports the player is no longer in combat (!= eCombatState_Combat), it sets m_combatEndPending = true and records m_leftCombatTime. When the game again reports eCombatState_Combat, UpdateCombatState clears m_combatEndPending and the fight continues (line 922).

PENDING_END to IDLE

If the elapsed time since m_leftCombatTime exceeds settings.battleEndDelay (default 10 seconds) without new damage, FinalizeBattle (MQMyDPS.cpp:926) executes. It creates a BattleData struct, calculates DPS and average damage, std::moves currentTargets and currentHealTargets into the battle record, sends a summary report to MQMyChat, publishes the battle to peers via actors.PublishFinalizedBattle() (MQMyDPS.cpp:972), and pushes the battle to battleHistory.

Why the delay?

Brief non-combat windows are common in EQ: a mob running to reset, fear/root breaking, or transitioning between linked encounters. The default 10-second delay covers most of these cases. Players can adjust battleEndDelay in the config window (stored as [Options] BattleEndDelay in the INI).

Settings Persistence

INI Location

Settings are stored per-character, per-server:

[MQ Config Dir]\MQMyDPS\[Server]\[CharName].ini

The directory tree is auto-created by SaveCharacterSettings (MQMyDPS.cpp:493) via std::filesystem::create_directories() on the parent path.

Save Triggers

  • Config Save button in the UI
  • Plugin shutdown (Shutdown() calls SaveCharacterSettings)
  • Character select (UnloadCharacterSettings calls SaveCharacterSettings)
  • Zone transition (OnBeginZone calls SaveCharacterSettings)

Load Trigger

SetGameState(GAMESTATE_INGAME) calls LoadCharacterSettings() (MQMyDPS.cpp:348). If the INI file does not exist, all settings retain their compiled defaults.

[FCTIcons] Section

Dynamic key/value pairs. Each key corresponds to an FCT type key from GetFCTTypeInfoList(). Values are integer icon IDs. A value of -1 means "use default icon logic." A value of FCT_ICON_NONE disables the icon for that type. Positive values override with a specific spell/item icon ID.

[Colors] Section

Each key in settings.damageColors is stored as an MQColor via WritePrivateProfileColor/GetPrivateProfileColor. An additional background key stores settings.bgColor. Color keys correspond to damage type color keys (e.g., hit, non-melee, dot, crit, heal, etc.).

Float Range Clamping

Warning: All float settings are read with MQ's typed GetPrivateProfileFloat() helper and range-clamped immediately after parsing. If a value falls outside the valid range, it is reset to its compiled default. This prevents corrupted INI files from causing rendering issues. (Int and bool keys use GetPrivateProfileInt() / GetPrivateProfileBool(); floats are written back with WritePrivateProfileFloat().)

Session Aggregation

The engine maintains two levels of target tracking: per-battle (currentTargets/currentHealTargets) and per-session (cachedSessionTargets/cachedSessionHeals). Session data accumulates across all battles and is never cleared except by /mydps reset.

Data Flow

When RecordDamage processes a hit, it updates both the per-battle map entry and the per-session map entry simultaneously. It then sets aggregateDirty = true.

RefreshAggregates

RefreshAggregates (MQMyDPS.cpp:1013) runs in OnPulse (every 250ms) only when aggregateDirty is true. It rebuilds the sorted vectors:

  • sortedSessionTargets — all TargetDamageData entries from cachedSessionTargets, sorted by totalDamage descending
  • sortedSessionHeals — all HealTargetData entries from cachedSessionHeals, sorted by GetTotalHeals() descending

The Targets and Healing tabs in the main window read from these pre-sorted vectors rather than iterating and sorting the maps on every frame. This decouples the rendering cost from the data size.

Tip: The dirty flag pattern means that if no new damage arrives, RefreshAggregates is a no-op. During heavy combat with many targets, the sort runs at most 4 times per second (250ms throttle), which is more than sufficient for UI refresh.
