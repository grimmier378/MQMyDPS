Cross-Character Sharing

MQMyDPS shares live DPS, session totals, and finalized battles between your boxed characters so the Group tab and the peer live-meter can show everyone at once. It is built on MacroQuest's post office actor system, with protobuf as the wire format. The whole subsystem lives in MyDPSActors.cpp / MyDPSActors.h, the schema in Proto/mydps.proto (compiled to Proto/mydps.pb.cc / .pb.h), and an optional bridge to the MQMyChat plugin in MyChatAPI.h.

No server traffic. Messages travel only between MacroQuest instances on the same machine (or however the post office is bridged). Each client publishes its own stats and listens for everyone else's on a shared mailbox.

  +---------------------------------+             |
      ^                                           |
      |   OnReceive(msg)  <----- mailbox "mydps" --+

      |        +-- kSession -> update PeerRecord.session*
      |        +-- kBattle  -> append PeerRecord.battles (max 50)

      |
      v   VisiblePeers(filterMode)  ->  Peers tab / peer live-meter

Mailbox & Self-Filtering

The mailbox name is the constant kMailbox = "mydps" (MyDPSActors.cpp:14). Publishing posts an envelope to Address{ Mailbox = "mydps" }; the post office echoes it to all subscribers including the sender, so every OnReceive branch first rejects its own messages with ci_equals(msg.character(), m_character) before updating a peer. Rejected self-echoes bump m_selfIgnoredCount; parse failures bump m_parseFailCount (both shown by DebugDump).

Timing & Pruning

All intervals are constants at the top of MyDPSActors.cpp and are enforced inside Pulse() against std::chrono::steady_clock:

ConstantValueGoverns
kLiveInterval1 sHow often LiveSnapshot is published
kSessionInterval3 sHow often SessionStats is published
kPruneInterval5 sHow often the stale sweep runs
kStaleAfter60 sA peer with no message for this long is erased
kMaxPeerBattles50Max battles kept per peer (FIFO eviction)

Every received message refreshes that peer's lastSeen. PruneStale (MyDPSActors.cpp:441) erases any peer where now - lastSeen > kStaleAfter, so a character that logs out or stops boxing disappears from the Peers tab within a minute.

Peer Filter Modes

PeerFilterMode (MyDPSActors.h:16) controls which peers VisiblePeers returns. The UI radio buttons and the /mydps filter command both write the integer into settings.peerFilterMode.

ModeIntIncludes
All0Every known peer
SameServer1Peers where ci_equals(peer.server, m_server)
SameGroup2Same server and in your group roster
SameRaid3Same server and in your raid roster

For Group/Raid modes the roster is built fresh each call from GetLocalGroupNames() / GetLocalRaidNames() (walking pLocalPC->Group up to MAX_GROUP_SIZE and pRaid->RaidMember up to MAX_RAID_SIZE), and membership is tested with the case-insensitive ContainsName helper (MyDPSActors.cpp:60). The local character is always pushed first via BuildSelfRecord().

The Self Record

BuildSelfRecord() (MyDPSActors.cpp:457) reconstructs m_selfRecord from live engine state on every VisiblePeers call — battle accumulators, GetBattleDPS()/GetSessionDPS()/GetBattleDuration(), and the last kMaxPeerBattles entries of battleHistory. This keeps "you" on the Peers tab perfectly in sync without round-tripping through the post office. Its color is assigned at Init via PeerColorForName() (a deterministic FNV-1a hash into a 12-entry palette), and re-assigned in BuildSelfRecord() if still at the default white.

PeerRecord & PeerBattle

See Types & Constants for the full field lists. In short: PeerRecord holds identity (server, character, classShort, isSelf), the live* block (from LiveSnapshot), the session* block (from SessionStats), a std::deque<PeerBattle> battles (from FinalizedBattle, capped at 50), a UI color, and a lastSeen timestamp.

MQMyChat Bridge (MyChatAPI.h)

MyChatAPI.h declares the ChatAPI plugin interface exported by the separate MQMyChat plugin. It is retrieved at runtime with GetChatAPI(), which wraps mq::GetPluginInterface("MQMyChat") and returns nullptr when MQMyChat is not loaded. The engine uses it to route battle reports to a named chat channel — see MQMyChat Integration. This bridge is independent of the actor/protobuf peer sharing described above.

Protobuf is generated. Proto/mydps.pb.cc and .pb.h are committed but generated from mydps.proto. If you change the schema, regenerate them rather than hand-editing. See Building.
