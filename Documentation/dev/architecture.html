Architecture

High-Level Design

MQMyDPS is organized into 5 layers. The engine owns all state. The pattern engine uses Blech B-tree pattern matching to parse chat text into structured records. The renderer reads engine state to draw the UI. The TLO exposes engine state to macros. The actors layer publishes the engine's stats to other boxed characters over the post office and aggregates incoming peer data. The renderer and TLO are read-only consumers—they never write to the engine.

Data Flow

OnIncomingChat(line)
    → ProcessChat()
        → MyDPSPatternEngine::Feed()  →  DamageRecord
        → RecordDamage()
            → ResolveSpawnID()  (6 strategies)
            → Update currentTargets / currentHealTargets
            → FCTManager.AddEntry()
            → Push to recentRecords

OnPulse (250ms)
    → TrackDoTCasting()
    → UpdateCombatState()  (FinalizeBattle → actors.PublishFinalizedBattle)
    → CleanExpiredRecords()
    → RefreshAggregates()
    → actors.Pulse()  (publish live/session, prune stale peers)

actors mailbox "mydps"
    → OnReceive(envelope)  →  update PeerRecord cache

OnUpdateImGui
    → (own + make-current the imanim context; host drives the clock)
    → RenderMainWindow()   (6 tabs incl. Peers; myui::PillTabBar)
    → RenderPopOutWindows()
    → RenderConfigWindow()
    → RenderCombatSpam()
    → RenderFloatingText()
    → RenderIconPicker()
